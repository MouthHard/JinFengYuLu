## 重要说明：命令执行环境

> ⚠️ **这是最容易出错的地方！请务必理解。**

### 两个不同的终端环境

| 环境 | 如何打开 | 执行的命令 |
|------|----------|-----------|
| **本地 PowerShell** | Windows Terminal / PowerShell | `npm run dev`, `npx vite build`, `scp`, `tar` |
| **远程 SSH** | 执行 `ssh ubuntu@<SERVER_IP>` 后进入 | `bash update.sh`, `mysql`, `pm2`, `curl` |

### 关键区别

```powershell
# ❌ 错误：在本地 PowerShell 执行服务器命令
ssh ubuntu@<SERVER_IP> cd /home/ubuntu && bash update.sh
# 这会导致：ssh 只执行第一个命令就断开连接

# ✅ 正确：分两步执行
# 第1步：登录服务器（在本地 PowerShell）
ssh ubuntu@<SERVER_IP>
# 第2步：在 SSH 会话中执行命令（此时已在服务器上）
cd /home/ubuntu
bash update.sh
```

### SSH 会话中的多行命令

**可以**在 SSH 会话中粘贴多条命令，它们会按顺序执行：

```bash
# SSH 会话中直接粘贴这三行，会按顺序执行
cd /home/ubuntu
bash update.sh
curl http://localhost/ | head -5
```

### 判断当前在哪个环境

- 命令以 `PS D:\...>` 开头 → **本地 PowerShell**
- 命令以 `ubuntu@...:~$` 开头 → **远程 SSH（服务器）**

## 1. 更新场景总览

| 场景 | 需要打包 | 需要上传 | 需要重启 |
|------|----------|----------|----------|
| 只改前端（页面/样式/图片） | `deploy-update.tar.gz` | 是 | Nginx reload |
| 只改后端（API逻辑） | **两个都要** | 是 | PM2 restart |
| 数据库变更（加数据/改表） | SQL 脚本 | 是 | 无 |
| 前后端同时改动 | 两个包都打包 | 是 | Nginx + PM2 |

> **重要**：`update.sh` 需要 `deploy-update.tar.gz` 始终存在（包含 nginx.conf 和 ecosystem.config.cjs），即使只改后端也要上传前端包。后端包 `server-dist-update.tar.gz` 现在是可选的。

## 2. 场景一：只改前端

> 修改页面布局、样式、新增图片资源等

### 第一步：本地开发预览

```powershell
cd "d:\Program Files\项目\PersonalWebsite"
npm run dev
```

在浏览器 `http://localhost:5173` 验证功能正常。

### 第二步：打包构建

```powershell
# 确保使用 production 模式（VITE_BASE=/）
npx vite build
```

**验证构建结果**：

```powershell
# 检查 index.html 路径是否正确（应该是 /App/ 而不是 /Personal-Website/App/）
Select-String -Path dist\index.html -Pattern "preload"
```

### 第三步：打包部署包

```powershell
cd "d:\Program Files\项目\PersonalWebsite"

# 清理临时目录
Remove-Item -Recurse -Force "tmp-deploy" -ErrorAction SilentlyContinue

# 创建临时目录并复制文件
New-Item -ItemType Directory -Force -Path "tmp-deploy" | Out-Null
Copy-Item -Recurse -Force dist "tmp-deploy\dist"
Copy-Item -Force "deploy\nginx.conf" "tmp-deploy\nginx.conf"
Copy-Item -Force "deploy\ecosystem.config.cjs" "tmp-deploy\ecosystem.config.cjs"
Copy-Item -Force "deploy\update.sh" "tmp-deploy\update.sh"

# 打包
Set-Location tmp-deploy
tar -czf "..\deploy-update.tar.gz" dist nginx.conf ecosystem.config.cjs update.sh
Set-Location ".."
Remove-Item -Recurse -Force "tmp-deploy"

Write-Host "Done: deploy-update.tar.gz 已生成"
```

### 第四步：上传到服务器

```powershell
scp deploy-update.tar.gz ubuntu@<SERVER_IP>:/home/ubuntu/
```

### 第五步：服务器执行更新

```bash
ssh ubuntu@<SERVER_IP>
cd /home/ubuntu
bash update.sh
```

`update.sh` 会自动完成：
1. 备份当前版本
2. 强制清除旧 dist（避免残留文件问题）
3. 部署新 dist
4. 更新 Nginx 配置
5. 重启后端服务（仅当存在 `server-dist-update.tar.gz` 时）
6. 重载 Nginx
7. 自动验证部署结果（路径、API、图片、代码内容）

### 第六步：浏览器验证

- 打开 `http://<SERVER_IP>`
- 按 **Ctrl+Shift+R** 强制刷新（清除浏览器缓存）


## 6. 服务器常用命令速查

### PM2 后端管理

```bash
pm2 status                          # 查看服务状态

pm2 logs personal-website-api --lines 50  # 查看最近50行日志
```

## 7. 回滚方案

每次部署 `update.sh` 会自动创建备份：`/var/www/personal-website-backup-YYYYMMDD-HHMMSS`

### 回滚步骤

```bash
# 1. 查看有哪些备份
ls -la /var/www/personal-website-backup*

# 2. 回滚到指定版本（替换时间戳）
sudo rm -rf /var/www/personal-website
sudo mv /var/www/personal-website-backup-20260807-120000 /var/www/personal-website

# 3. 重启服务
cd /var/www/personal-website
pm2 delete personal-website-api 2>/dev/null || true
pm2 start ecosystem.config.cjs
pm2 save

# 4. 重载 Nginx
sudo nginx -t && sudo systemctl reload nginx
```

## 8. 常见问题排查

### 问题：服务器上修改的代码不生效

```bash
# 1. 确认 update.sh 已完成（看到 "Deployment Complete!" 提示）
# 2. 检查 update.sh 的代码内容验证步骤是否通过
#    最后一步会显示 "Code verified" 或 "WARNING: Code may not be updated"

# 3. 手动检查服务器上的文件
# 检查 index.html 是否是最新的
curl -s http://localhost/ | head -10

# 检查 JS 文件内容（验证新代码是否真的被部署）
JS_FILE=$(curl -s http://localhost/ | grep -o 'assets/js/index-[^"]*' | head -1)
curl -s "http://localhost/assets/js/$JS_FILE" | grep -o "children\[0\]" | head -1

# 4. 如果验证不通过，重新执行 update.sh
cd /home/ubuntu && bash update.sh
```

### 问题：浏览器缓存导致更新不生效

这是最常见的问题！即使服务器端文件已更新，浏览器可能仍在使用旧的缓存。

**解决方案（按推荐度排序）**：

| 方法 | 操作 | 适用场景 |
|------|------|---------|
| 强制刷新 | `Ctrl + Shift + R` | 快速验证 |
| 清除缓存 | `Ctrl + Shift + Delete` → 勾选缓存 → 清除 | 彻底解决 |
| 无痕模式 | 打开浏览器无痕窗口访问 | 临时测试 |
| 禁用缓存 | F12 → Network → 勾选 "Disable cache" | 开发调试 |

**根本原因**：Nginx 对 `/assets/` 路径配置了 `expires 30d` + `Cache-Control: public, immutable`，虽然 Vite 使用 hash 文件名来确保新文件有新 URL，但浏览器可能缓存了旧的 `index.html`（它引用了旧的 JS 文件名）。

### 问题：CSS background 简写被覆盖

`SolarSystem.scss` 中 `#sun` 使用了 `background: #000000` 简写属性，会同时设置 `background-image: none`，导致 Vue 内联样式的 `background-image: url(...)` 失效。

**解决方案**：将 CSS 中的简写 `background: #000000` 改为独立属性 `background-color: #000000`。

```css
/* ❌ 错误：简写会覆盖 background-image */
background: #000000;

/* ✅ 正确：独立属性不影响 background-image */
background-color: #000000;
```

### 问题：button 元素默认外观阻止自定义样式

`<button>` 标签在所有浏览器中有默认的 `appearance` 样式，会阻止自定义 `background` 显示。

**解决方案**：在 CSS 中添加重置样式。

```css
button {
  appearance: none;
  -webkit-appearance: none;
  border: 0;
  outline: none;
}
```

### 问题：前端页面白屏

```bash
# 1. 检查 index.html 是否正确
curl -s http://localhost/ | head -20

# 2. 检查 JS/CSS 文件是否可达
curl -sI http://localhost/assets/js/index-xxxxx.js | head -3

# 3. 检查 Nginx 错误日志
sudo tail -20 /var/log/nginx/error.log
```

### 问题：图片不显示

```bash
# 1. 检查图片文件是否存在
ls -la /var/www/personal-website/dist/App/

# 2. 检查 Nginx 是否能返回图片
curl -sI http://localhost/App/Sun.webp | head -3

# 3. 检查 index.html 中的路径是否正确
# 正确：href="/App/Sun.webp"
# 错误：href="/Personal-Website/App/Sun.webp"
curl -s http://localhost/ | grep "preload"

# 4. 如果路径是 /Personal-Website/，说明构建模式错误
# 本地用 npx vite build 重新构建（不要用 --mode gh-pages）
```

### 问题：API 返回 502

```bash
# 1. 检查后端服务是否运行
pm2 status

# 2. 检查后端日志
pm2 logs personal-website-api --lines 30

# 3. 重启后端
pm2 restart personal-website-api
```

### 问题：路径错误（/Personal-Website/ vs /）

这是最常见的问题。根因是构建时使用了错误的模式。

```bash
# 验证当前部署的路径
curl -s http://localhost/ | grep "preload"

# 正确输出应该包含：href="/App/Sun.webp"
# 错误输出会包含：href="/Personal-Website/App/Sun.webp"
```

**解决方法**：确保本地用 `npx vite build` 构建（默认 production 模式，`VITE_BASE=/`），不要使用 `--mode gh-pages`。

## 注意事项

1. **构建模式**：始终用 `npx vite build`（production 模式），不要用 `--mode gh-pages`
2. **部署前备份**：`update.sh` 会自动备份，无需手动操作
3. **强制清除旧文件**：`update.sh` 会在解压前 `sudo rm -rf` 旧 dist，避免残留
4. **数据库变更**：先本地测试，再上服务器执行
5. **回滚备份**：定期清理旧备份 `sudo rm -rf /var/www/personal-website-backup-*`（保留最近3个）
6. **强制刷新**：每次部署后浏览器必须 `Ctrl+Shift+R` 强制刷新
7. **前端包必须上传**：即使只改后端，也必须上传 `deploy-update.tar.gz`（包含 nginx.conf 和 ecosystem.config.cjs）
8. **CSS 样式注意**：
   - 避免使用 `background` 简写，改用 `background-color`
   - `<button>` 元素必须添加 `appearance: none` 重置默认外观
9. **代码验证**：`update.sh` 最后一步会验证 JS 代码内容，确保新代码已部署
10. **update.sh 清理问题**：`update.sh` 执行完毕后会删除自身（Cleanup 步骤）。下次部署时需要先从 `deploy-update.tar.gz` 中解压 `update.sh`，再执行。正确命令：`tar -xzf deploy-update.tar.gz update.sh && bash update.sh`
11. **API 502 启动延迟**：`update.sh` 验证步骤中 API 可能返回 502（后端刚重启还未就绪），等待 3-5 秒后自行恢复，无需处理
12. **部署配置路径**：`nginx.conf` 中 `root` 指向 `/var/www/personal-website/dist`，`ecosystem.config.cjs` 中 `cwd` 指向 `/var/www/personal-website/server`，与 `update.sh` 的部署路径一致

## 9. 快速部署速查（一键复制）

> 以下命令可直接复制到本地 PowerShell 执行，适用于最常见的"只改前端"场景。

### 场景 A：只改前端（最常用）

```powershell
# 1. 构建（在项目根目录）
npx vite build

# 2. 打包
Remove-Item -Recurse -Force "tmp-deploy" -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force -Path "tmp-deploy" | Out-Null
Copy-Item -Recurse -Force dist "tmp-deploy\dist"
Copy-Item -Force "deploy\nginx.conf" "tmp-deploy\nginx.conf"
Copy-Item -Force "deploy\ecosystem.config.cjs" "tmp-deploy\ecosystem.config.cjs"
Copy-Item -Force "deploy\update.sh" "tmp-deploy\update.sh"
Set-Location tmp-deploy
tar -czf "..\deploy-update.tar.gz" dist nginx.conf ecosystem.config.cjs update.sh
Set-Location ".."
Remove-Item -Recurse -Force "tmp-deploy"

# 3. 上传
scp deploy-update.tar.gz ubuntu@<SERVER_IP>:/home/ubuntu/

# 4. 部署（先解压 update.sh 再执行）
ssh ubuntu@<SERVER_IP> "cd /home/ubuntu && tar -xzf deploy-update.tar.gz update.sh && bash update.sh"

# 5. 验证（等待 5 秒后）
Start-Sleep -Seconds 5
ssh ubuntu@<SERVER_IP> "curl -sI 'http://localhost/api/aphorism?page=1&limit=1' | head -3"
```
